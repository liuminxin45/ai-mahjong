# 连续牌局验收

条件、步骤与结果对应 SDK 7.0.1。自动结果保存在 `artifacts/journey/` 与覆盖率输出中。发布时另记录完整源码提交与宿主提交。

| 范围 | 条件与操作 | 预期 | 自动化入口 |
| --- | --- | --- | --- |
| 物理牌 | 15 开局逐一检查；210 条路径任意后续选择 | 每事件恰好 72 个唯一副本，每牌种四张，无多摸或凭空消失 | `tsx scripts/verify-journey.ts` |
| 胜负 | 自摸、接炮、四个席位和牌及流局样本 | 成牌由独立完整目标枚举核对；流局确实摸空牌墙 | 同上；`journey.test.ts` |
| 第一章 | 三种开局分别打出任意一张 | 剩余十三张不变，至少还有一次玩家出牌机会 | `journey.test.ts` |
| 信息边界 | NPC 选牌、画像重建 | NPC 只获自身手牌与牌河；报告不把墙内实际牌当作先前已知 | 单元与宿主服务测试 |
| 首尾配对 | 比较三个第一章与第五章开局 | 自有牌相同、已知牌不同，最佳牌效选择实际不同；统计不翻倍 | 单元与独立复核 |
| 重试并发 | 相同命令再提交、旧序号、新局收到旧回复 | 不多打牌、不覆盖当前输入；冲突命令拒绝 | 单元、浏览器 |
| 阅读 | 明确身份后入局，提前和牌后继续章末 | 场景不被胜负截断；第四、五章没有现在的妹妹实时回应 | 全路径、浏览器 |
| 连续呈现 | 三家自动行动、玩家再摸一张，中间穿插对白 | 十三张 DOM 保留；只有新牌出现；有序牌河对应实际事件 | 浏览器元素存活检查 |
| 存储 | 自动摸打中刷新、回到页面 | 按已存命令恢复一次；不重新洗墙；阅读位置和已呈现标记留下 | 单元、浏览器 |
| 节奏 | 正常／减少动态效果，菜单与后台切换 | 自动呈现和有效计时暂停；不突然补播；重复提交不跨两手 | 浏览器与人工录屏 |
| 资源 | 冷启动、热刷新、坏字节、失败重试、无存储 | 校验与解码全部完成才开门；热刷新不重复请求音频 | 资源单元、两浏览器 |
| 画像 | 五局内多次选择、重复旅程、不同难度 | 只显示真实选择数；不同档不合并；少样本只谈某一手 | 单元与服务测试 |
| 模型约束 | 不存在的观察、自问、证据、额外人格字段 | 失败闭合，留本地数据供主动重试 | 宿主 `test:mahjong` |
| 私有报告 | 生成、缓存、读取、异客读取／删除、过期、超时 | 同身份可读删、异客不可，失败可重试 | 真实 SQL RPC 测试、正式站点 |
| 布局 | Chromium / WebKit，1920/1280/768/390/360/320，各两主题 | 无水平溢出，所有选牌目标至少 44px，弹窗可 Escape 退出 | `test:journey-browser` |

自动检查实际完成情况：新旧合计 321 项单元通过；连续牌局核心逐文件分支覆盖超过 95%。独立牌数与完整和型检查走过 210 条路径、5,862 个事件，九种席位／结束方式可复现。两种浏览器都已通关五章，选择次数随合法终局自然变化，原牌实体存活、中途刷新、菜单暂停、重复提交及热刷新无新增音频请求通过。小屏目标检查发现的 360px 不足 44px 已修正，最终宽度矩阵已通过。

Windows Playwright WebKit 没有可用音频后端，该平台的声音接口为测试替身；原始字节、网络、缓存、剧情和布局仍实际检查。Chromium 使用原生解码与播放器。Linux CI WebKit 使用真实解码。仿真截图不能作为实体手机、来电中断或完整听审的证据。

`test:journey-pacing` 用原始音频字节的本地传输夹具验证原生 Chromium 播放、逐行650ms淡入、动作文字延迟700ms再淡入1000ms，以及菜单暂停；动作按钮保持居中。真实 GitHub 来源与正式域名另做无网络替身检查。

尚需人工验证：五名未玩过的用户，至少四名在一分钟内说清“我是谁、替谁打、现在该做什么”，三次摸打后能指出刚舍出的牌与新摸的牌；故事是否自然、音乐是否影响思考、真机触屏和来电恢复。未邀请或代替真人填写结果，仍记为待验证。
