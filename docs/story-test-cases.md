## 制作与兼容约定

- 35 张制作卡直接保存在 `src/story/catalog.json`：局面、题目版本、证明、注记时间归属及声音章次均可复建。`story:verify` 不依赖作者工作目录。
- `story:build` 是新版本的作者工具，使用经过搜索的候选集；候选搜索入口为 `scripts/build-experience.ts`。发布后的故事文件禁止原地改写；新题需另设内容版本。
- 全部历史都上传重判，交给模型的是分层统计与代表事实；音乐、静音、剧情跳过不进入画像。
- 旧题 332 个 ID 与答案不变。旧画像接口、旧快照、旧草稿保留；旧页面不继续提供导航。`/legacy-app` 仅供兼容后端先行发布与回滚。
- 音频固定引用资产提交 `a4f4604cdeb77cb1d769e068e3e7c46fa714317a`，发布包仅含清单，不能包含 MP3／WAV；图像使用内容版本目录。
- 关键算法及判分每文件分支、行、函数、语句均要求 95%；服务门禁 90%。独立算法核验继续保留。

## 人工验证边界

自动化覆盖浏览器仿真、完整音频解码、响度标准化和加载流程。实体手机、来电中断、真人难度标定、完整音乐听审及故事情感试玩必须单独记录，不能以仿真截图或音轨元数据代替。当前没有这些人工结果。

本机 Windows Playwright WebKit 缺少 Web Audio 和原生音频解码器。该引擎本地测试为声音接口提供显式夹具，只验证布局、交互、存档及真实文件摘要；Chromium 使用实际解码。Linux Playwright CI 不启用声音夹具，检查真实 WebKit 解码。WebKit 的私密上下文会在导航时丢弃 CacheStorage，因此暖缓存测试使用全新持久上下文，并在测试后清理；这与用户普通浏览窗口一致。音频由本地 HTTP 夹具提供原始字节，不拦截协议网络；真实 GitHub 下载另验。模型服务在页面检查中使用夹具，正式域名的真实模型请求另记。各种结果不能互相替代。

## 发布和回滚

1. 音频先提交到公开源码仓库，确定 SHA。
2. 源码测试通过后生成固定 SHA 的发布包；宿主更新同一固定依赖。
3. 先用 `/legacy-app` 发布兼容新旧画像的后端，正式域名验证快照 6 和旧快照。
4. 再切到故事入口并发布；验证完整五章、真实 GitHub 请求、暖缓存、真实模型生成、读取和删除。
5. 回滚只恢复固定依赖和兼容服务。浏览器答题、旧草稿及云端历史保持不动。首页作品时间和最新内容规则不调整。
