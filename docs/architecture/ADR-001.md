# ADR-001：前端技术栈选型（Vite + TypeScript + PixiJS + Vitest）

- **状态（Status）**：已采纳（Accepted）
- **决策日期**：基于代码现状反向梳理（无独立决策记录，结论来自 `package.json` / `vite.config.ts` / `tsconfig.json`）
- **决策者**：原始实现团队

## 背景（Context）

本项目是一个**纯前端、可离线运行的成都麻将 AI 教学平台**，需在浏览器内完成：完整对局模拟、AI 决策、LLM 教练、回放、画像、以及 Node 端的自对弈训练与 AI 评测。约束：

1. 无后端服务依赖（部署到 Vercel 静态托管 + 单函数代理即可）。
2. 需用 TypeScript 保证麻将规则/算法的类型安全（`Tile`/`Action`/`GameState` 等强类型）。
3. 需具备单元测试能力（规则正确性、EV 算法、LLM 路由）。
4. 需支持「开发期本地代理 LLM、生产期 Serverless 代理」的密钥隔离。

## 决策（Decision）

采用 **Vite 6 + TypeScript 5（strict）+ PixiJS 8（依赖层）+ Vitest 2 + Vercel Serverless + pnpm** 的组合：

- 构建/Dev：`vite.config.ts`（dev proxy 注入 LLM key）；`package.json` 中 `dev/build/preview/test/train/ai-eval` 脚本齐全。
- 类型与质量：`tsconfig.json` 开启 `strict`、`noUnusedLocals`、`noUnusedParameters`、`noFallthroughCasesInSwitch`。
- 单测：`vitest.config.ts`（`environment: 'node'`），`tests/` 与 `src/**/*.test.ts` 共 174 用例全绿。
- 部署：`vercel.json` 指定 `buildCommand: pnpm build`、`outputDirectory: dist` 与 SPA rewrite。
- 包管理：`package.json` 声明 `packageManager: pnpm@9.15.0`、`engines.node: 20.x`。

## 后果（Consequences）

**正面**
- 零后端即可运行；Vercel 静态托管成本低、冷启动快。
- TS 强类型显著降低麻将规则实现出错率（如 `Action` 判别联合类型贯穿全栈）。
- Vite 极快 HMR，适合频繁调参的教学 UI；Vitest 与 Vite 共享配置，测试零额外成本。
- dev proxy（`vite.config.ts:9-44`）让本地无需暴露厂商密钥即可联调 LLM。

**负面 / 风险**
- `vite build` 使用 esbuild，**不执行类型检查**；类型错误不会阻断构建（见 REVIEW §CI）。
- 单仓库同时承载「浏览器运行期」与「Node 训练脚本」，部分模块依赖 `typeof window`/`typeof fs` 做双端分支（如 `paramPersistence.ts:35`），增加认知负担。
- `pixi.js` 作为依赖存在但实际未被运行期使用（见 ADR-002），是冗余依赖。

## 备选方案（Alternatives Considered）

| 方案 | 结论 |
|---|---|
| CRA / Webpack | 否决：构建慢、配置重，Vite 更契合纯前端 SPA。 |
| 纯 JS（无 TS） | 否决：麻将规则与 EV 算法类型复杂，无类型风险过高。 |
| Jest 替代 Vitest | 否决：Vitest 与 Vite 同源配置、ESM 原生、速度快。 |
| 引入 BFF / 自建后端 | 否决：超出 MVP 范围，Vercel 单函数代理已满足密钥隔离。 |
