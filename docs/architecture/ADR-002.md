# ADR-002：渲染与游戏状态分离（含 PixiJS 现状说明）

- **状态（Status）**：已采纳（Accepted），但**实现存在偏差**——PixiJS 路径当前为孤儿代码，运行期实际由 DOM/CSS 渲染。
- **决策日期**：基于代码现状反向梳理
- **决策者**：原始实现团队

## 背景（Context）

麻将 UI 需要把高频变化的 `GameState` 呈现为牌桌、手牌、弃牌河、碰杠、阶段切换与过场动画。若渲染逻辑与游戏规则/状态耦合，会带来：规则改动牵连 UI、UI 重构牵连引擎、难以单测。目标原则：**游戏规则（core/rules）与渲染（ui）互不依赖，UI 通过「状态快照 → 呈现器」单向消费状态**。

## 决策（Decision）

确立「**单一事实源 Store + 快照订阅 + 纯呈现器**」模式：

- `gameStore`（`src/store/gameStore.ts`）持有 `state` 与 `events`，每次 `applyState`/`pushEvent` 产生**新引用**并 `emit()`。
- UI 在 `renderMatch`（`src/ui/pages/match.ts:117`）订阅 `gameStore`，以 `render()` 作为纯函数从快照重建视图；交互通过 `ctx.orchestrator.dispatchHumanAction(action)` 回写，**UI 不持有游戏规则**。
- 设计上预留了一条 **PixiJS canvas 路线**：`src/ui/pixi/MahjongTableScene.ts` 暴露 `update(state, evs)` 的快照式 API（`:192`），`DiscardZone`/`OpponentHand`/`CompassRose` 为无状态的呈现子组件，符合「状态与渲染分离」的正确形态。

### ⚠️ 现实偏差（已核实，非臆测）

经全仓 `grep` 确认：

- `src/ui/pixi/*` 中 `MahjongTableScene`、`DiscardZone`、`OpponentHand`、`CompassRose`、`TileSprite`、`TileTextureCache` **仅在 pixi/ 目录内部相互引用，全代码库无任何外部 import**（证据：`grep -rn "ui/pixi" src` 仅命中 pixi/ 自身）。
- **实际 TABLE 模式渲染是 100% DOM/CSS**：`src/ui/renderers/matchTableRenderer.ts`（`renderTableMode`）与 `renderers/matchDebugRenderer.ts` 直接构建 `pixel-*` 元素，并订阅 `gameStore`；DEBUG 模式同理（`renderers/matchDebugRenderer.ts`）。
- 因此 `pixi.js`（v8.17.1）依赖在运行期未被使用（Vite 会 tree-shake 掉未被引用的模块），并未带来 GPU 渲染。PixiJS 场景是「已落地但未被接入的候选实现」。

## 后果（Consequences）

**正面**
- DOM/CSS 渲染路线已被验证可用、可访问（含 `aria-label`/`aria-hidden`，见 `matchTableRenderer.ts`）、易调试，且零额外运行时依赖。
- 快照订阅模式使「状态 ↔ 视图」方向严格单向，规则引擎完全不感知 UI。

**负面 / 风险**
- **孤儿代码**：完整 PixiJS 场景未被接入，属维护负担与误导（新成员可能误以为牌桌走 canvas）。
- **全量重渲染**：`render()` 每次 `emit` 以 `innerHTML=''` 重建整页 DOM（`matchTableRenderer.ts:48`、`match.ts:75`），对超长对局/低端设备存在性能上限（见 REVIEW §性能）。
- **双渲染路线并存**：DOM 与 PixiJS 两套呈现抽象（`renderers/*` vs `pixi/*`）增加了理解成本。

## 备选方案（Alternatives Considered）

| 方案 | 结论 |
|---|---|
| 仅 DOM/CSS（现状实际采用） | 保留：零依赖、可访问、已验证。 |
| 纯 PixiJS 牌桌 + DOM HUD | 曾规划（pixi/ 场景即此意图）；未接线，建议**要么接入、要么删除**，消除歧义。 |
| 框架（React/Vue）管理视图 | 否决：引入框架与虚拟 DOM，超出轻量 SPA 定位；当前订阅式原生渲染足够。 |
| 状态管理库（Redux/Zustand） | 否决：自研轻量 `subscribe/emit` Store 已满足，避免额外依赖。 |
