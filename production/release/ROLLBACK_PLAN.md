# 回滚预案（Rollback Plan）— v0.1.0

> neo-mahjong · 成都麻将 AI 教学平台 · 2026-08-14
> 目标：发布后出现严重问题时，能在最短时间内回到稳定状态。

---

## 1. 触发回滚的条件（满足任一即考虑回滚）

| 级别 | 条件 | 动作 |
|------|------|------|
| P0 | 对局流程卡死 / 无法完成一局 / 结算大面积错误 | **立即回滚** |
| P0 | 页面打不开、白屏、构建产物损坏 | **立即回滚** |
| P1 | 计分错误影响多数对局 / LLM 教学输出严重错误 | 评估后回滚或热修 |
| P2 | 局部 UI/音效异常、不影响核心对局 | 不回滚，走热修/下版本 |

## 2. 回滚方式

### 方式 A：Vercel 部署回滚（最快，推荐）
Vercel 保留每次部署的历史版本，无需改代码：
1. 打开 Vercel 项目控制台 → **Deployments**。
2. 找到上一个正常部署（本轮发布前的那次）。
3. 点 **⋯ → Promote to Production**（或 Redeploy），即刻回切。
- 耗时：约 1 分钟内生效。
- 适用：本次发布引入问题、上一版正常。

### 方式 B：git revert（代码层回滚）
当需要撤销本次发布的提交时：
```bash
# 回滚到发布前最后一个稳定提交 314547a（逐个 revert 本轮 3 个提交）
git revert f533a06 aadbe57 43f93f4 --no-edit
git push origin main
# Vercel 会基于新 push 自动重新部署
```
- 适用：需要从代码上彻底撤销、且保留历史记录（不产生 force push）。
- 稳定锚点：`314547a`（Phase 2-6 之前的状态）。

### 方式 C：紧急 force 回退（仅极端情况，慎用）
```bash
git reset --hard 314547a
git push origin main --force
```
- ⚠️ 会改写远端历史，仅当方式 A/B 都不可行且确认为单人仓库时使用。
- 操作前必须本地备份当前分支：`git branch backup-before-rollback`。

## 3. 已知风险点与缓解

| # | 风险 | 缓解 |
|---|------|------|
| R1 | 本机 `pnpm build` 被 WorkBuddy 沙箱拦截（vite 清空 dist 被 genie-safe-delete 拦截） | **非项目缺陷**。Vercel CI 无此拦截；本地可用 `vercel --prod` 让云端构建，或绕开沙箱构建 |
| R2 | LLM 代理 `/api/llm/kimi/messages` 依赖 `KIMI_API_KEY` 环境变量 | 部署前确认 Vercel 环境变量已配；缺失时 LLM 教练不可用但不影响核心对局 |
| R3 | 音频 AudioContext 在个别浏览器需用户手势后才出声 | 已是设计行为（无自动播放合规）；首次点击"开始游戏"即激活 |
| R4 | 新增 6 色 LUT 在低端设备上有逐像素开销 | LUT 仅 6 色精确匹配 + 缓存键含色彩模式，开销可控；异常可在设置切回原色 |
| R5 | 英文模式不渲染牌面图片（已知缺口） | 发布说明已标注；英文用户退化为文本牌，不影响规则正确性 |

## 4. 回滚后验证

回滚完成后，按 `RELEASE_CHECKLIST.md` §3 的冒烟清单重新验证核心对局流程，
确认回到稳定状态后再定位本次发布的问题根因。

## 5. 责任与记录

- 回滚决策：由产品负责人（用户）拍板，主理人执行。
- 每次回滚须在 `production/release/` 追加一条记录（时间、触发条件、采用方式、结果）。
